# Техническое задание: PWA «ТурВайб»

## 1. Назначение

«ТурВайб» — минималистичное мобильное PWA для поиска и сравнения баз отдыха, отелей и глэмпингов. Пользователь задаёт даты, состав гостей, общий бюджет и предпочтения; приложение мгновенно показывает только доступные варианты и помогает сравнить от двух до четырёх объектов.

Первый этап работает полностью на mock-данных, без внешнего API и сервера.

## 2. Целевая платформа и дизайн

- Mobile-first интерфейс с контейнером до 430 px при просмотре на десктопе.
- Русский язык интерфейса.
- Одностраничное приложение без перезагрузок при изменении параметров.
- Визуальный стиль: природная палитра, крупная типографика, компактные карточки; акцентный цвет — лаймовый.
- PWA-основа: `manifest.json`, тема приложения и service worker для кэширования локальных ресурсов.

## 3. Функциональные требования

### 3.1. Главный экран: поиск и фильтрация

Пользователь может:

- выбрать дату заезда и дату выезда;
- указать число взрослых (минимум 1) и детей (минимум 0);
- установить максимальный бюджет ползунком — сумма применяется ко всему сроку проживания, а не к одной ночи;
- включить несколько тегов предпочтений: «Рыбалка», «SPA / Бассейн», «С животными», «В лесу», «Завтрак включён»;
- изменить сортировку списка по цене.

Все изменения должны применять фильтр на клиенте мгновенно.

### 3.2. Правила фильтрации

Для каждого объекта рассчитывается список ночей от даты заезда включительно до даты выезда исключительно. Объект попадает в результат, только если одновременно:

1. Дата выезда позже даты заезда.
2. Ни одна ночь не входит в `booked_dates` объекта.
3. `price_per_night × количество_ночей` не превышает выбранный бюджет.
4. Объект содержит все активные теги предпочтений.

При пустой выдаче пользователь видит понятное сообщение с предложением изменить бюджет или фильтры.

### 3.3. Карточки результатов

Каждая карточка содержит:

- качественное превью;
- название и локацию;
- пользовательский рейтинг;
- процент совпадения с запросом;
- итоговую цену за весь выбранный период;
- кнопку добавления или удаления из сравнения.

В верхней части выдачи показываются число подходящих вариантов и количество ночей.

### 3.4. Выбор и сравнение

- В сравнении может быть от 2 до 4 объектов.
- После выбора первого объекта появляется плавающая нижняя панель с числом выбранных карточек.
- Пока выбрано меньше двух объектов, переход к сравнению недоступен.
- При попытке добавить пятый объект показывается короткое уведомление.
- На экране «Баттл баз» доступны возврат к поиску и очистка выбора.

### 3.5. Экран «Баттл баз»

Экран сравнения должен быть читаемым на смартфоне: верхние карточки объектов прокручиваются горизонтально, ниже находится сравнительная таблица.

Для каждого варианта выводятся:

- итоговая стоимость за период без скрытых сборов;
- локация / удалённость;
- наличие бассейна или SPA;
- наличие бани;
- включён ли завтрак;
- возможность проживания с питомцем;
- главный плюс и нюанс варианта по отзывам (моковые данные).

Под таблицей приложение показывает рекомендуемый «вайб-выбор»: вариант с лучшим сочетанием рейтинга и совпадения с запросом.

## 4. Локальная модель данных

Источник данных: `hotels_data.json`. На текущем этапе он содержит 15 объектов.

```json
{
  "id": "forest",
  "name": "Глэмпинг «Лесной Вайб»",
  "location": "Боровое · 12 км от центра",
  "price_per_night": 24500,
  "booked_dates": ["2026-09-12", "2026-09-13"],
  "features": ["wi-fi", "pool", "banya", "pet_friendly", "breakfast", "forest"],
  "rating": 4.9,
  "match": 98,
  "image_url": "https://...",
  "plus": "Главное преимущество",
  "minus": "Что стоит учесть"
}
```

Допустимые ключи `features`: `wi-fi`, `pool`, `banya`, `pet_friendly`, `breakfast`, `forest`, `fishing`, `lake`.

## 5. Состав проекта

| Файл | Назначение |
| --- | --- |
| `index.html` | Структура SPA: поиск, результаты, сравнение. |
| `styles.css` | Адаптивный mobile-first дизайн. |
| `app.js` | Состояние, фильтрация, расчёт итоговой цены, рендеринг и взаимодействия. |
| `hotels_data.json` | Локальная mock-база объектов. |
| `manifest.json` | Метаданные устанавливаемого PWA. |
| `sw.js` | Кэширование локальных файлов для офлайн-основы. |

## 6. Критерии приёмки

1. При выборе дат 15–18 сентября в выдаче отсутствуют объекты, у которых в `booked_dates` есть 15, 16 или 17 сентября.
2. Итоговая цена равна цене за ночь, умноженной на число ночей; бюджет ограничивает именно эту сумму.
3. Включённый тег исключает все объекты без соответствующей услуги.
4. Список обновляется без перезагрузки страницы.
5. Пользователь может добавить, удалить и сравнить 2–4 объекта.
6. В сравнении видны цена, локация, услуги и моковые плюс/минус каждого выбранного объекта.
7. Интерфейс остаётся удобочитаемым в ширине 320–430 px.

## 7. Ограничения первого этапа

- Доступность, рейтинги и отзывы являются тестовыми данными.
- Нет оплаты, бронирования, личного кабинета и интеграции с внешними сервисами.
- Изображения берутся по URL; для полной офлайн-работы их следует перенести в локальные ассеты на следующем этапе.
